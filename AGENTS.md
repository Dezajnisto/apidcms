# apidcms — правила работы

Lightweight PHP CMS: SQLite + Twig, встроенный AI-ассистент, установка за минуту.
Публичный продукт — репозиторий видят все, кто пользуется CMS.

- Версия: `www/core/VERSION` (сейчас 2.2.5) — единственный источник правды
- Схема версионирования и релизный чек-лист: `VERSIONING.md`
- История изменений: `www/CHANGELOG.md`
- Формы и их API: `FORMS.md`

## Структура

```
www/
├── core/                  ядро (то, что раскатывается на сайты)
│   ├── VERSION            текущая версия
│   ├── bootstrap.php      инициализация, автозагрузка
│   ├── router.php         входная точка маршрутизации
│   ├── src/
│   │   ├── Admin/         контроллеры админки (BaseController — общий предок)
│   │   ├── Api/           REST API (articles, tables, auth)
│   │   ├── Core/          Database, AI, ExternalPageLoader, I18n, Plugin* и пр.
│   │   └── Front/         фронтенд-контроллеры и рендеринг страниц
│   ├── views/             Twig-шаблоны админки
│   ├── lang/              ru.json / en.json — ключи переводов
│   ├── assets/            css/js админки
│   └── config/            дефолтные конфиги (пользовательские — вне ядра)
├── install.php            установщик (INSTALLER_VERSION)
├── init_system_tables.php
└── storage/               данные сайта: database/, uploads/, cache/, logs/
```

## Правила

- **Совместимость важнее красоты.** Ядро стоит на живых сайтах; ломающие изменения
  — только с повышением MAJOR и записью в `CHANGELOG.md`.
- **Данные сайта — вне ядра.** Всё, что пишется в рантайме (база, кэш, логи,
  загруженные файлы, конфиги пользователя), живёт в `www/storage/` и `www/config/`,
  никогда внутри `www/core/`. Это правило уже нарушалось (кэш документации,
  `pd_consent.log`) — при правке проверять, что новые файлы не пишутся в ядро.
- **SQL — только через `Core\Database`** с подготовленными выражениями. Никаких
  склеек строк в запросах.
- **Экранирование в шаблонах.** Twig автоэкранирует; `|raw` — только там, где
  содержимое уже прошло санитайз, и с комментарием почему.
- **Тексты интерфейса — только через ключи** `lang/ru.json` + `lang/en.json`.
  Добавил ключ в один язык — добавь во второй в том же коммите.
- **Плагины** живут в `www/plugins/<name>/` со своим `plugin.json` (манифест:
  имя, версия, зависимости). Настройки плагина — в БД, не в файле манифеста.
- **Проверки безопасности**: файлы вне веб-корня или с 403 (`/config/`, `/core/`,
  `/storage/database/`), загрузки — по белому списку расширений и реальному MIME,
  админка — за авторизацией.

## Релиз

Порядок и чек-лист — в `VERSIONING.md`. Коротко: `VERSION`, `INSTALLER_VERSION`,
`www/CHANGELOG.md`, git-тег и запись в changelog на сайте должны совпадать.
Версия без записи в changelog — незаконченный релиз.

## Чего не делать

- Не добавлять в публичный репозиторий внутренние адреса, имена сайтов, пути
  локальных машин, пароли и ключи — это публичный код.
- Не коммитить `www/storage/`, `www/config/*.php` с реальными паролями, `vendor/`
  изменения без причины.
- Не менять формат `plugin.json` и сигнатуры публичных API без записи в
  `CHANGELOG.md` и без обратной совместимости.
